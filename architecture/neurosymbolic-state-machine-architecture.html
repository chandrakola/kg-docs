Overview

1. Executive Summary & Problem Context

The structural limits of the current file-based waterfall pipeline.

Historically, rwdkn-data-pipeline evolved as a sequential cascade of isolated CLI scripts:

flowchart LR S1[Stage 1: source-nexus] -->|Raw SPL/XML| S2[Stage 2: assertion-engine] S2 -->|Raw JSON Triples| S3[Stage 3: concept-align] S3 -->|Normalized JSON| S4[Stage 4: biolink-bridge] S4 -->|KGX TSVs| S5[Stage 5: quality-guardian] S5 -->|Post-Hoc Gate| S6[(Neo4j & Fuseki)]

While this batch architecture provided initial debugging checkpoints, it creates critical limitations:

  • Post-Hoc Validation Discard: When a triple fails domain/range rules in Stage 5, it is silently dropped hours later after the LLM prompt context has already terminated.
  • All-or-Nothing Ingestion Latency: Ingesting a single new drug label or five PubMed abstracts requires executing the full batch cascade.
  • Unverified Graph Leakage: Without deterministic state staging, unverified candidate assertions risk polluting production query stores.
Theoretical Foundation

2. Frank Coyle's 5 Core Principles

Key takeaways from UC Berkeley's AI Engineer World's Fair 2026 Presentation.

Principle Core Concept Application to REAL-KG
1. Neurosymbolic Dual-Process System 1 (LLM: fast, generative) paired with System 2 (Ontology: slow, formal, deductive). LLM proposes candidate assertions; Biolink / UMLS enforces deterministic boundaries.
2. Structural $\ne$ Semantic Validation Pydantic validates payload syntax/types; Ontologies validate real-world domain truth. (Metformin)-[:treats]->(Nausea) is valid JSON, but violates adverse reaction ontology semantics.
3. In-The-Loop Reflection Ontology validation executes immediately inside the generation loop, enabling LLM self-correction. Evaluate domain/range in-memory; prompt the LLM with the exact axiom violation while document context is hot.
4. Delay of Side-Effects & Quarantine Unverified agent actions must never commit side-effects directly to live systems. Stage assertions in PostgreSQL. Route borderline triples to /demo/triples/ for HITL clinical signoff.
5. Ontology-Guided Querying NLQ-to-graph translation must be bounded by the ontology metamodel. Pre-flight Cypher AST validation against Biolink schema prevents reversed edges and query hallucination.

Comparing Airflow, Event-Driven Streaming, and PostgreSQL State-Machine.

Path 1: Airflow Workflow DAG (Orchestrated Batch)

Replaces shell scripts with an Apache Airflow DAG in platform-services/airflow.

Path 2: Event-Driven Streaming (RabbitMQ + S3 / KEDA)

Converts pipeline stages into distributed microservice workers consuming AMQP message queues.

AspectRatingAnalysis
In-The-Loop ReflectionComplexRequires coordinating multi-turn LLM reflections over distributed message brokers.

HITL Clinical ReviewDifficultMessage queues are ephemeral; clinical auditing requires external persistence.
Refactoring ScopeVery HighDemands RabbitMQ cluster, KEDA scaling, dead-letter exchanges, and distributed tracing.
Verdict: An over-engineered operational distraction that solves streaming latency without solving clinical quality.

Path 3: Database State-Machine & Audit Ledger (RECOMMENDED)

Optimal Neurosymbolic Fit

Uses PostgreSQL as an immutable clinical state ledger and HITL quarantine buffer, running ontology checks inside the extraction worker loop.

AspectRatingWhy Path 3 Wins
In-The-Loop ReflectionNativeWorker validates candidate triples in-memory and prompts for reflection before DB write.
Delay of Side-EffectsGuaranteedNeo4j and Fuseki only ingest APPROVED triples; unverified assertions cannot leak.

Refactoring ScopeMinimalReuses existing PostgreSQL instance in shared-infra and existing LinkML SDKs.

How it works: Each statement enters Stage 1. Inner Loop 1 guarantees syntactic and verbatim quote integrity. Inner Loop 2 in Stage 2 guarantees entity resolution. Stage 3 acts as the formal ontology verifier. If Stage 3 finds an axiom violation, the statement recurses back to Stage 1 with explicit feedback data. If it fails a second time, the circuit breaker breaks recursion and routes the triple to the HITL quarantine layer in /demo/triples/.

Python Implementation Pattern: Recursion with Break

orchestration/hierarchical_statement_loop.py 
MAX_RECURSION_DEPTH = 1  # 1 initial pass + 1 reflective retry turn

def process_statement(statement_context: dict, feedback: dict = None, depth: int = 0):
    """
    Hierarchical Statement Processor:
    - Inner loops guarantee local syntactic & normalization correctness.
    - Outer loop guarantees global ontological truth with recursive circuit breaker.
    """
    # -------------------------------------------------------------------
    # STAGE 1: assertion-engine (Inner Loop 1: Syntax & Quote Match)
    # -------------------------------------------------------------------
    candidate_triples = assertion_engine_inner_loop(
        statement=statement_context["text"],
        section=statement_context["section"],
        feedback=feedback  # Contains diagnostic if depth > 0
    )
    if not candidate_triples:
        return {"status": "NO_ASSERTIONS"}

    # -------------------------------------------------------------------
    # STAGE 2: concept-align (Inner Loop 2: Entity Disambiguation)
    # -------------------------------------------------------------------
    grounded_triples = concept_align_inner_loop(candidate_triples)

    # -------------------------------------------------------------------
    # STAGE 3: quality-guardian (Ontology Axiom Verification)
    # -------------------------------------------------------------------
    audit_results = quality_guardian_verify(grounded_triples, statement_context)

    # ===================================================================
    # THE OUTER LOOP: BREAK OR RECURSE
    # ===================================================================
    if audit_results.is_valid:
        # BREAK 1: SUCCESS -> Commit and move to next statement
        save_to_postgres(grounded_triples, status="SEMANTICALLY_VALID")
        return {"status": "SUCCESS", "depth": depth}

    # If ontology violation occurred:
    if depth < MAX_RECURSION_DEPTH:
        # RECURSE: Feed the exact ontology diagnostic back to Stage 1
        reflection_feedback = {
            "prior_attempt": candidate_triples,
            "violations": audit_results.violations,
            "instruction": audit_results.correction_advice
        }
        return process_statement(statement_context, feedback=reflection_feedback, depth=depth + 1)
    else:
        # BREAK 2: CIRCUIT BREAKER -> Delay side-effects (HITL Quarantine)
        save_to_postgres(grounded_triples, status="QUARANTINED_HITL", violations=audit_results.violations)
        return {"status": "QUARANTINED", "reason": audit_results.violations}

8. Ontology-Constrained Cypher Guard for NLQ

Principle 5: Pre-validating Cypher ASTs before database execution in query-app.

In query-app/query_translator/cypher_generation.py, LLM-generated Cypher is checked against the ontology metamodel before hitting Neo4j:

query_translator/cypher_ontology_guard.py 
def validate_cypher_ontology_ast(cypher_query: str) -> List[str]:
    """Validate Cypher AST against Biolink domain/range constraints."""
    errors = []
    
    # 1. Reverse Traversal Check
    # (:Disease)-[:TREATS]->(:Drug) is semantically invalid
    if re.search(r"\(:Disease[^)]*\)-\[:TREATS\]->\(:Drug", cypher_query):
        errors.append(
            "ONTOLOGY_DIRECTION_INVERTED: 'TREATS' must traverse from (:Drug) to (:Disease). "
            "Please invert the relationship arrow."
        )

    # 2. Hallucinated Relationship Type Check
    invalid_rels = {"CAUSES_SIDE_EFFECT", "MEDICATES", "DRUG_FOR"}
    for rel in invalid_rels:
        if f"[:{rel}]" in cypher_query:
            errors.append(f"INVALID_BIOLINK_PREDICATE: '{rel}' does not exist in KG schema.")

    return errors
