Section 01 // Executive Paradigm Comparison & 3-Tier Classification

Architectural Brief: Distinguishing Intrinsic Paradigm Differences from Implementation Choices

Biolink Model v4.3.6 + Neo4j 5.26.28 CE

Tier 1 Intrinsic Semantic Advantages (RDF / OWL / SHACL)

Capabilities formally guaranteed by W3C specifications where domain semantics are declared once in the ontology/shapes rather than reconstructed by application code:

  • Formal Transitive Subsumption (RDFS/OWL): W3C RDFS formally defines rdfs:subClassOf and rdfs:subPropertyOf as transitive; instances of a subclass or sub-property are automatically entailed as instances of their superclasses/super-properties.
  • Portable Closed-World Shapes & Rules (SHACL): Declarative sh:NodeShape constraints and sh:TripleRule inferences (e.g., inferring rwdkn:isMonotherapy) execute before graph ingestion.
  • Global IRIs & W3C PROV-O: Native semantic alignment across RXCUI:, SNOMEDCT:, MESH:, MED-RT:, ATC:, and MTHSPL:.

Tier 2 Modern Neo4j 5.26 Capabilities (Now Adopted)

Database and Cypher capabilities supported by our deployed neo4j:5.26.28 engine that were underutilized in v1 and have now been adopted across the codebase:

  • GQL-Conformant Quantified Relationships: Replaced artificial 1-hop bounds ([:SUBCLASS_OF*0..1]) with arbitrary-depth quantified path patterns (-[:SUBCLASS_OF]->* and -[:SUBCLASS_OF]->+).
  • Dynamic Node Labels & Relationship Types: Cypher 5.26+ supports dynamic type/label expressions (MATCH (s)-[r:$($rel_types)]->(o:$($object_labels))) populated from a single centralized semantic planner.
  • Native Uniqueness Constraints: Enforces 5 native IS UNIQUE constraints in Neo4j 5.26 Community Edition (while noting property existence/type & Graph Types require Enterprise Edition).

Tier 3 RWDKN v1 Pipeline Defects (Remediated in Codebase)

Shortcomings traced to specific v1 pipeline and query-template implementation choices rather than Neo4j or the LPG paradigm itself—all fixed and regression-tested:

  • Order-Independent Canonical Typing: Replaced first-seen-wins deduplication in export_kgx.py with reconcile_node_records() and ancestor label expansion.
  • Centralized Biolink Hierarchy: Moved class and predicate closures out of individual Cypher templates into semantic_query_planner.py (including RELATED_TO).
  • Mandatory MATCH in Regimen Loader: Replaced historical OPTIONAL MATCH with mandatory MATCH-before-MERGE and post-load connectivity assertions.

Section 03 // Points #2, #3 & #5: Multi-Hop Taxonomies & Centralized Class Expansion

Interactive Hierarchy Explorer: Native RDFS Entailment vs. Quantified Cypher Paths

-[:SUBCLASS_OF]->* + Centralized Biolink Closure

In v1, two implementation choices in cypher_templates.py caused brittleness and recall loss: (1) an artificial 1-hop bound [:SUBCLASS_OF*0..1] that omitted 2-hop drug Xultophy (RXCUI:1727493), and (2) hardcoded child label pipes Disease|ClinicalFinding|Phenotype|PhenotypicFeature inside individual templates. While W3C RDFS natively defines rdfs:subClassOf as transitive (an intrinsic RDF advantage), Neo4j 5.26 supports GQL-conformant quantified relationships (-[:SUBCLASS_OF]->* / -[:SUBCLASS_OF]->+) and centralized class-closure expansion in semantic_query_planner.py.

In rwdkn-shacl-shapes.ttl and shacl_validation.py, W3C RDFS formally defines rdfs:subClassOf as transitive without application-side closure tables:

# 2. Transitive SPARQL Class Query (Unbounded Hops):
SELECT ?drug ?drugName WHERE {
    ?drug rdfs:subClassOf+ <http://id.nlm.nih.gov/mesh/M0160181> ;

# Automatically returns: semaglutide, dulaglutide, liraglutide,
# AND 2-hop combination drug Xultophy (RXCUI:1727493)!

Neo4j 5.26 Remediated Quantified Paths & Centralized Closure

In semantic_query_planner.py and cypher_templates.py, v1's 1-hop bound and scattered label lists were replaced with centralized Biolink closure and GQL quantified relationships: 

# 1. semantic_query_planner.py — Centralized Biolink subclass closure:
_CLINICAL_OBJECT_LABELS = "|".join(
    expand_biolink_class_closure("DiseaseOrPhenotypicFeature")
)

// 2. cypher_templates.py — GQL-conformant quantified relationship:
// Replaces v1 [:SUBCLASS_OF*0..1] with arbitrary-depth -[:SUBCLASS_OF]->*
MATCH (s:Drug|ChemicalEntity)-[:SUBCLASS_OF]->*(class:DrugClass)
WHERE class.id IN $class_ids OR s.id IN $class_ids
// Now traverses 2+ hops to reach Xultophy (RXCUI:1727493)!

Section 05 // Points #6 & #7: Regimen Connectivity & Native Database Constraints vs. SHACL

Mandatory MATCH Semantics, Neo4j 5.26 CE/EE Constraints & Declarative SHACL Rules

neo4j:5.26.28 CE vs. Enterprise Graph Types vs. SHACL

In Competency Question 5 (CQ-5: Concomitant Regimen & Combination Therapy Rules), an indication or adverse event is conditioned on a multi-drug or lifestyle regimen (e.g., Wegovy RXCUI:1991302 is indicated for Obesity SNOMEDCT:414916001 only in combination with a Weight Reduction Diet SNOMEDCT:289169006 AND Exercise Therapy SNOMEDCT:229065009). Reviewing our CQ-5 verification incidents (2026-08-30-cq5-regimen-choice-implementation-verification.md) clarifies two critical points: (1) the 19/19 detached regimen incident was caused by using OPTIONAL MATCH for a functionally mandatory parent Association, and (2) stating that Neo4j has "NO native schema/shape validation" is overly broad—we must distinguish between Neo4j 5.26 Community Edition constraints, Neo4j Enterprise Edition / 2025 Graph Types, and higher-order SHACL shapes & conditional rules.

RDF + SHACL Declarative Closed-World Shapes & sh:TripleRule

In rwdkn-regimen-shapes.ttl, value enumerations, minimum cardinality, and conditional rule inference (`sh:TripleRule`) are expressed declaratively in a portable W3C standard: 

rwdkn:RegimenChoiceGroupShape a sh:NodeShape ;
    sh:targetClass rwdkn:RegimenChoiceGroup ;
    sh:property [
        sh:path rwdkn:regimenOption ;
        sh:minCount 1 ;
        sh:node rwdkn:RegimenOptionShape ;
    ] ;
    # Declarative SHACL Rule: automatically infers monotherapy!
    sh:rule [
        a sh:TripleRule ;
        sh:subject sh:this ;
        sh:predicate rwdkn:isMonotherapy ;
        sh:object true ;
        sh:condition [
            sh:property [ sh:path rwdkn:selectionBehavior ;
                          sh:hasValue "none" ]
        ]
    ] .

Architectural Conclusion: Complementary Roles of RDF/OWL/SHACL and Modernized Neo4j 5.26

Separating intrinsic semantic guarantees from remediated v1 implementation defects sharpens our architectural conclusion. Modernizing our Neo4j 5.26 implementation—using deterministic node reconciliation, centralized Biolink class/predicate closures in semantic_query_planner.py, GQL quantified relationships (-[:SUBCLASS_OF]->*), dynamic type expressions ([r:$($rel_types)]), and mandatory MATCH semantics—eliminates the four recall/orphan bugs identified in v1. At the same time, RDF / OWL 2 / SHACL retains a genuine architectural advantage as the authoritative semantic contract layer: class and property subsumption (rdfs:subClassOf, rdfs:subPropertyOf), closed-world shape validation (sh:NodeShape), and conditional rule inference (sh:TripleRule) are declared once in portable W3C standards rather than maintained in ~2,940 LOC of custom Python projection and query-planning code.
