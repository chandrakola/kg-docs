OpenAI Model Selection Recommendation

Default: gpt-5.6-terra with medium reasoning. Keep Luna for routine, low-risk volume and Sol for unusually difficult or high-risk work.

Evidence reviewed

The activity window was 2026-08-03 through 2026-08-10.

  • GitHub: 11 repositories pushed, 88 authored commits on default branches, and 10 pull requests opened and merged.
  • Local checkout: 101 commits reachable across local refs, about 311 repository-file entries touched, and about 89,658 insertions versus 4,921 deletions.
  • Large line counts were dominated by generated ontology, SHACL, schema, fixture, audit, and release artifacts.
  • Representative work included stateful Docker volumes, Airflow, Proxmox and Cloudflare deployments, federation routing, LinkML/SHACL contracts, PostgreSQL promotion/rollback, and release verification.

This is not mainly frontier algorithm research, but it is context-heavy and operationally consequential. Terra is a safer everyday balance than Luna, while Sol is unnecessary for most individual tasks.

Automatic model selection

Current official OpenAI API guidance documents explicit model selection. The gpt-5.6 alias routes to gpt-5.6-sol; it is not a task-aware cost router. No official API setting was found that dynamically chooses Sol, Terra, or Luna from request complexity.

Use Terra as a fixed default with explicit escalation, or implement a small client-side router using task labels such as routine, implementation, and high-risk. If a Codex client shows an Auto option, verify its actual model selection and billing for your account.
